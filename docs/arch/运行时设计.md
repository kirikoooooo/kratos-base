# 1.运行时设计

## 目的

AgentRuntime 是本系统的核心执行引擎：接收自然语言任务，通过 LLM 进行对话推理，调用本地工具（读/写/编辑文件、执行命令）完成代码相关的实际工作，并将结果返回给调用方。

具体目标：
- **多角色协作**：支持 Router、Coder、Reviewer 等多种 Agent 角色，每个角色有不同的系统提示词和可用工具，可相互委派子任务
- **工具驱动执行**：通过 function calling 机制，让 LLM 自主决定何时调用何种工具，工具结果回传给 LLM 继续推理
- **自愈与容错**：工具调用失败时，错误信息格式化后回传 LLM，让其修正参数后重试（最多 5 轮；exec_command 最多 3 次）
- **远程委派**：支持通过 gRPC 将子任务委派给远程 Agent 节点执行
- **后端可替换**：通过 ChatClient 抽象，支持 langchaingo 或 OpenAI 原生 SDK 两种 LLM 调用方式

## 思路

### 核心设计理念：Actor 模型 + 端口/适配器

运行时采用 **Actor 模型** 接收任务——每个 AgentRuntime 实例是一个独立的 Actor（PID 9001），通过 mailbox 接收异步消息。这带来了天然的并发安全性和背压控制。

对外暴露的是 **端口接口**（`biz/agent_runtime.AgentRuntime`），实现在 data 层——遵循 DDD 分层架构，biz 层只依赖抽象，不依赖任何具体的 LLM SDK。

### Agent 角色路由

```
用户输入
  │
  ▼
RouterAgent ──拆解任务──► CoderAgent ──实现代码──► ReviewerAgent ──审查反馈
  │                           │                       │
  │                           ▼                       ▼
  │                     工具调用（read/edit/write/delete/exec）
  │                           │
  └───────────────────────────┴──── 最终结果返回用户
```

- **RouterAgent**：负责拆解复杂任务，调度 Coder/Reviewer 子 Agent
- **CoderAgent**：负责实际编码实现，可反向委托 Router 重新规划
- **ReviewerAgent**：纯 LLM 审查（无工具调用），给出评审意见
- **DefaultAgent**：通用模式，直接调用本地工具完成任务

### 工具调用循环（Tool Calling Loop）

```
┌─────────────────────────────────────────────────┐
│  System Prompt + 历史对话 + 用户问题              │
│                      │                           │
│                      ▼                           │
│  ┌───── LLM Chat API（带工具定义）──────────┐    │
│  │  模型决定：直接回复 or 调用工具            │    │
│  └──────────────────┬───────────────────────┘    │
│                     │                             │
│          ┌──────────┴──────────┐                  │
│          ▼                     ▼                  │
│     文本回复              工具调用请求             │
│          │                     │                  │
│          ▼                     ▼                  │
│     返回结果           执行工具 handler            │
│                              │                    │
│                    ┌─────────┴─────────┐          │
│                    ▼                   ▼          │
│               成功 → 回传结果    失败 → 回传错误   │
│                                         + hint    │
│                              │                    │
│                              ▼                     │
│                    继续下一轮（最多 12 轮）        │
│                    纠错轮数 ≤ 5                    │
└─────────────────────────────────────────────────┘
```

循环终止条件：
1. LLM 返回纯文本（无工具调用）→ 正常结束
2. 工具连续失败达 5 轮 → 触发失败分析提示词，让 LLM 输出中文失败报告
3. 总循环达 12 轮 → 同上，输出失败分析
4. 远程 Agent 委托 → 最终结果合并后返回

### 对话上下文管理

每轮对话的完整历史（user/assistant/tool 消息）被持久化到 `AgentMemory`。每次调用 LLM 前，runtime 会：
1. 加载历史对话 turns
2. 通过 `PrepareTurnsForLLMWithMeta` 评估是否需要压缩（阈值 200,000 字符）
3. 若超阈值，压缩旧轮次的 tool 输出并省略中间轮次，保留最近 24 轮
4. 注入用户自定义的提示词调优记忆
5. 在每次 tool calling loop 迭代中重复上述压缩检查

### 后端可替换性

```
ChatClient（biz 层接口）
    │
    ├── LangChain 适配器 ──► llms.Model ──► langchaingo/llms/openai ──► OpenAI API
    │                                                         └──► DeepSeek API
    │
    └── OpenAI 原生客户端 ──► go-openai SDK ──► OpenAI API
```

通过 `ChatClientProvider` 工厂模式，provider 的选择在 data 层决定，运行时通过 `ChatClient` 接口交互，不感知底层 SDK。

### 核心接口

#### AgentRuntime（biz/agent_runtime/repository.go）

```go
type AgentRuntime interface {
    actorpkg.Actor                          // Actor 模型：PID, Process, OnStop
    Name() string
    Supports(AgentKind) bool
    Execute(ctx, AgentKind, prompt) → TaskResult   // 同步执行
    ReceiveTask(ctx, TaskCommand) → TaskResult      // 接收任务命令
    SendTask(ctx, TaskCommand) → TaskResult         // 通过 actor mailbox 异步执行
}
```

#### AgentKind（角色枚举）

| 常量 | 角色 | 可用工具 | 可委派 |
|------|------|---------|--------|
| `AgentKindDefault` | 通用代理 | 全部本地工具 | - |
| `AgentKindRouter` | 路由器 | coder_agent, reviewer_agent | Coder, Reviewer |
| `AgentKindCoder` | 编码器 | 全部本地工具 + router_agent + reviewer_agent | Router, Reviewer |
| `AgentKindReviewer` | 审查者 | 无工具（纯 LLM） | - |

#### ChatClient（biz/chat/entity.go）

```go
type ChatClient interface {
    Chat(ctx, messages []ChatMessage, tools []ToolDef) → ChatResponse
}
```

neutral 消息结构，屏蔽 langchaingo/go-openai 的类型差异。

#### DelegationVerifier（可选扩展）

```go
type DelegationVerifier interface {
    VerifyDelegation(ctx, taskID, AgentKind, prompt) → TaskResult
}
```

用于 router → coder/reviewer 委派链路的验证，运行时在 `dispatchSubTask` 前记录 trace 事件，执行完成后标记验证结果。

### 关键数据结构

#### TaskCommand / TaskResult（protobuf 定义）

```protobuf
message TaskCommand {
  string task_id = 1;
  string agent   = 2;   // AgentKind 字符串
  string prompt  = 3;   // 用户自然语言指令
}

message TaskResult {
  string summary = 1;   // 简短摘要
  string output  = 2;   // 完整输出
}
```

这两个结构贯穿整个调用链——从 gRPC/CLI 入口，经过 biz 层，到 data 层运行时的 `Execute`/`ReceiveTask`/`SendTask`。

#### langChainAgentRuntime（data 层实现）

```go
type langChainAgentRuntime struct {
    config             *conf.AI                // AI 配置（provider、api_key 等）
    runtimeConfig      *conf.Runtime           // 运行时配置（远程 Agent 列表）
    log                *log.Helper
    pid                actorpkg.PID            // PID 9001, name "langchain-runtime"
    trace              DelegationTraceStore    // 委派追踪
    memory             AgentMemory             // 对话记忆与持久化
    chatClientProvider ChatClientProvider      // ChatClient 工厂
    localTools         *agenttool.Runtime      // 本地工具运行时
    toolCatalog        *toolcatalog.Catalog    // 工具定义目录
}
```

### 工具系统

本地工具通过 `toolcatalog.Catalog` 统一管理——工具 JSON 定义嵌入在 `third_party/tools/*.json` 中，运行时加载后转为 `ToolDef` 传递给 `ChatClient`。

| 工具 | 功能 | 风险等级 |
|------|------|---------|
| `read_file` | 读取文件内容或列出目录 | 低 |
| `write_file` | 创建新文件（不允许覆盖） | 中 |
| `edit_file` | 增量编辑：insert/delete/replace 行或字符串 | 中 |
| `delete_file` | 删除文件（CLI 模式下需确认） | 高 |
| `exec_command` | 执行 shell 命令（CLI 模式高风险需确认） | 高 |

### 调用链路（完整）

```
1. gRPC/CLI/Web 入口
   │
2. TaskUsecase.Create(agent, prompt)
   │  ├── 生成 task ID
   │  ├── 保存 Task（Status: pending）
   │  └── TaskDispatcher.Dispatch(task)
   │
3. TaskDispatcher.Dispatch
   │  ├── 验证 runtime 可用 & 支持该 AgentKind
   │  ├── 注册 runtime 为 Actor（若未注册）
   │  └── go handle(task)   // 异步执行
   │
4. TaskDispatcher.handle
   │  ├── 加载 task → 标记 running
   │  ├── StartConversation（memory）
   │  ├── StartTask（trace）
   │  ├── runtime.SendTask(cmd)  → 通过 actor mailbox
   │  └── 标记 done/failed → 更新 task → 记录 trace 事件
   │
5. AgentRuntime.Process(msg)   // Actor 消息处理
   └── ReceiveTask(cmd)
       └── Execute(ctx, agent, prompt)
           │
6. Execute ──► runDefault/runRouter/runCoder/runReviewer
   │
7. runToolCallingLoop   // 核心工具调用循环
   │  ├── 构建 system prompt + memory context
   │  ├── 加载历史对话 turns
   │  ├── 压缩上下文（若需要）
   │  ├── ChatClient.Chat(messages, tools)
   │  │     ├── 文本响应 → 结束循环
   │  │     └── 工具调用 → 执行 handler
   │  │           ├── 成功 → 回传结果 → 下一轮
   │  │           └── 失败 → 格式化错误 + hint → 下一轮
   │  ├── 持久化对话（memory）
   │  ├── 发布进度事件（trace）
   │  └── 超限 → 失败分析 → 返回 TaskResult
   │
8. TaskResult 沿调用链返回
```

### 关键参数

| 参数 | 值 | 说明 |
|------|---|------|
| `MaxToolLoopIterations` | 12 | 单次对话最大工具循环轮数 |
| `MaxToolCorrectionRounds` | 5 | 工具连续失败最大纠错轮数 |
| `MaxExecCommandAttempts` | 3 | exec_command 单任务最大调用次数 |
| `DefaultRemoteTimeout` | 8s | 远程 Agent gRPC 调用超时 |
| `RuntimeMailboxSize` | 128 | Actor mailbox 缓冲大小 |
| `DefaultCompressThreshold` | 200,000 字符 | 上下文压缩触发阈值 |
| `DefaultKeepRecentTurns` | 24 | 压缩后保留的最近轮数 |
| `DefaultToolOutputMaxChars` | 8,000 | 单次工具输出最大字符数 |

## 与其他模块的关联

### 与 tasking（任务调度）模块

```
TaskUsecase ──创建 Task──► TaskDispatcher ──Dispatch──► AgentRuntime (Actor)
                              │
                              ├── StartConversation → memory
                              ├── StartTask → trace
                              └── SendTask → runtime (通过 Actor mailbox)
```

`tasking` 是 AgentRuntime 的入口调度层。`TaskDispatcher` 负责：
- 注册 AgentRuntime 为 Actor
- 将 TaskCommand 通过 Actor mailbox 发送给 runtime
- 在任务生命周期各阶段记录状态变更到 trace 和 memory

### 与 memory（对话记忆）模块

```
AgentRuntime
  │
  ├── StartConversation    → 创建新会话
  ├── LoadConversation     → 加载历史对话
  ├── SaveConversation     → 持久化每轮对话
  ├── PrepareForTask       → 准备任务上下文
  ├── RenderPromptContext  → 注入提示词调优记忆
  ├── PrepareTurnsWithMeta → 压缩 + 统计
  └── RecordSessionError   → 记录工具/LLM 错误
```

每次 tool calling loop 迭代都会：
1. 重新加载对话并检查压缩
2. 注入用户自定义的记忆上下文
3. 工具调用成功后记录工具使用统计
4. 工具失败后记录错误详情

### 与 trace（委派追踪）模块

```
AgentRuntime
  │
  ├── AppendEvent  → 记录 plan_presented/step_progress/agent_progress
  │                   delegate_local/remote, remote_execute_done/failed
  │                   context_compress, verification_start/done/failed
  ├── UpdateContextUsage → 发布上下文窗口利用率
  ├── StartTask / UpdateTask → 更新任务生命周期
  └── UpdatePlan → 更新执行计划步骤状态
```

trace 事件被 DashboardService 订阅，实时推送到 Web UI 和 CLI 界面显示执行进度。

### 与 session（文件变更追踪）模块

```
tool.Runtime
  │
  ├── read_file   → 记录基线
  ├── write_file  → 记录新建
  ├── edit_file   → 计算 diff → 记录变更
  └── delete_file → 记录删除
```

localTools 内部持有 `SessionStore`，每次文件操作后保存变更快照。Dashboard 可通过 trace 查看每个 session 的文件变更历史。

### 与 service 层（gRPC / CLI / Dashboard）

```
┌──────────────────────────────────────────────┐
│ gRPC: AgentRuntimeService.ExecuteTask()      │
│   → 暴露给远程节点调用（远程委派场景）         │

├──────────────────────────────────────────────┤

│   → 多 Agent 状态面板                         │
│   → 委派链路可视化                            │
│   → 文件变更 diff 查看                        │
└──────────────────────────────────────────────┘
```

### 与 provider（AI 厂商）模块

```
ChatClientProvider ──► LangChain adapter ──► LLMProvider ──► OpenAI / DeepSeek
```

- `OpenAIProvider`：默认模型 gpt-4o-mini，function calling 时 gpt-5* 降级
