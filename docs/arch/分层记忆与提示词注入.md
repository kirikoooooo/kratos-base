# 分层记忆与提示词注入

## 目的

AgentRuntime 在每次调用 LLM 之前，需要把「模型该扮演什么角色」「工具怎么用」「用户长期偏好」「本次会话上下文」「历史对话」「失败如何收尾」等信息，按不同生命周期和不同注入位置组织进一次请求。本文回答两个问题：

1. **分层记忆（Layered Memory）**——系统按什么粒度、存在哪里、保留多久地记住东西。
2. **提示词注入（Prompt Injection）**——不同类型的提示词分别在**哪一层数据**、**哪一个消息位置**被拼进 LLM 请求。

> 相关运行时循环见 [`运行时设计.md`](./运行时设计.md)。本文聚焦「记忆 + 提示词」这一横切面。

---

## 一、分层记忆设计

### 1.1 四层记忆模型

记忆按「作用域 × 生命周期」分为四层，全部由 `biz/memory` 定义领域结构，`data/memory` 以**文件 JSON**落地。

```
┌─────────────────────────────────────────────────────────────┐
│ ① 用户记忆 UserAgentMemory      作用域: 用户   生命周期: 长期  │
│    workspace_root / tool_hints / skill_hints                 │
│    command_policies / prompt_notes                           │
│    → 跨会话、跨任务持久保留，是"用户画像 + 调优偏好"           │
├─────────────────────────────────────────────────────────────┤
│ ② 会话记忆 SessionAgentMemory   作用域: 会话   生命周期: 中期  │
│    agent / tool_hints / command_policies                     │
│    prompt_notes / tools_used                                 │
│    → 单个 session 内累积，记录"本会话用过哪些工具、局部策略"    │
├─────────────────────────────────────────────────────────────┤
│ ③ 对话记忆 SessionConversation  作用域: 会话   生命周期: 工作集 │
│    turns[] (human / ai / tool 三种角色的完整轮次)             │
│    → 短期工作记忆，超阈值触发压缩，只保留最近 N 轮            │
├─────────────────────────────────────────────────────────────┤
│ ④ 错误记忆 SessionErrorRecord   作用域: 会话   生命周期: 滚动  │
│    time / stage / tool / message / detail                    │
│    → 追加写入，注入时只取最近 6 条，用于自我纠错              │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 各层字段与用途

| 层 | 结构体 | 关键字段 | 记什么 | 谁写入 |
|----|--------|---------|--------|--------|
| ① 用户记忆 | `UserAgentMemory` | `WorkspaceRoot`、`ToolHints`、`SkillHints`、`CommandPolicies`、`PromptNotes` | 用户长期偏好、工具/技能提示、命令策略、提示词覆盖 | `UpsertUserMemory`（外部主动写入） |
| ② 会话记忆 | `SessionAgentMemory` | `Agent`、`ToolHints`、`CommandPolicies`、`PromptNotes`、`ToolsUsed` | 本会话绑定的角色、局部策略、已用工具集 | `PrepareForTask` / `RecordSessionToolUsage` |
| ③ 对话记忆 | `SessionConversation` | `Turns[]`（`ConversationTurn`：human/ai/tool） | 完整对话历史（含工具调用与结果） | `StartConversation` / `SaveConversation` |
| ④ 错误记忆 | `SessionErrorRecord` | `Stage`、`Tool`、`Message`、`Detail` | 工具/LLM 失败详情，供下一轮修正 | `RecordSessionError` |
| 元数据字典 |  |  | 关键的元数据信息，不能依赖大模型的记忆。 |  |

> 定义位置：`internal/biz/memory/entity.go`。

### 1.3 落地形态（文件 JSON）

`data/memory` 的 `fileAgentMemoryStore` 在 `baseDir` 下建立四个子目录，一层记忆一个目录，一条记录一个 JSON 文件：

```
<memory dir>/
  ├── users/         <userID>.json          → UserAgentMemory
  ├── sessions/      <sessionID>.json        → SessionAgentMemory
  ├── conversations/ <sessionID>.json        → SessionConversation
  └── errors/        <sessionID>.*           → SessionErrorRecord（追加）
```

> 目录建立见 `internal/data/memory/store.go` 的 `ensureLayout()`；`userID` 缺省为 `default`。

### 1.4 接口分层（端口/适配器）

```
biz 层（端口）
  AgentMemoryStore  ── 纯持久化：LoadUser/SaveUser/LoadSession/SaveSession/
  │                    LoadConversation/SaveConversation/AppendSessionError/ListSessionErrors
  │
  AgentMemory       ── 领域编排：在 Store 之上叠加压缩、渲染、统计等业务逻辑
                       StartConversation / PrepareForTask / RenderPromptContext
                       PrepareTurnsForLLMWithMeta / RecordSessionError ...
                              │ 实现
data 层（适配器）
  agentMemoryUsecase (usecase.go)  +  fileAgentMemoryStore (store.go)
```

- `AgentMemoryStore`：只管「存/取」，无业务逻辑，实现是文件 JSON（`internal/biz/memory/repository.go`）。
- `AgentMemory`：领域接口，负责压缩、格式化、渲染注入块——运行时只依赖它（`internal/data/memory/usecase.go`）。

## 二、提示词注入设计

### 2.1 一次 LLM 请求的完整装配

所有提示词最终汇入 `runToolCallingLoop`（`internal/data/agent_runtime/runtime.go:449`）。装配顺序如下——**注意区分「system 文本拼接」与「message 历史追加」两种注入方式**：

```
                         ┌──────────────────────── system message ────────────────────────┐
systemText =             │                                                                 │
  ┌── A. 角色系统提示词  │  "你是 RouterAgent……"（按 AgentKind 选择）                      │
  │                      │        + "\n" +                                                 │
  ├── B. 工具使用规约    │  toolCallingSystemSuffix()（编辑/路径/执行流程/收尾约定）         │
  │                      │        + "\n\n## Agent Memory（提示词调优）\n" +                 │
  └── C. 记忆注入块      │  RenderPromptContext() = 用户记忆 + 会话记忆 + 最近 6 条错误      │
                         └─────────────────────────────────────────────────────────────────┘
                                                     │  BuildLLMMessages(systemText, turns)
                                                     ▼
  ┌── D. 对话历史        [system] + [human/ai/tool ...]  ← 来自 SessionConversation，压缩后注入
  │
  └── E. 失败分析指令    仅在工具循环失败/超限时，在消息尾部追加一条 [human] failureAnalysisInstruction
```

对应代码（runtime.go:453-473）：

```go
systemText := strings.TrimSpace(systemPrompt) + "\n" + toolCallingSystemSuffix()   // A + B
if r.memory != nil {
    if block := strings.TrimSpace(r.memory.RenderPromptContext(ctx, sessionID)); block != "" {
        systemText += "\n\n## Agent Memory（提示词调优）\n" + block                  // C
    }
}
// ... 加载对话、AppendHumanTurnIfNeeded、PrepareTurnsForLLMWithMeta（压缩）...
messages := agentcontext.BuildLLMMessages(systemText, turns)                        // D
```

### 2.2 五类提示词逐一说明

| 类型 | 来源 | 注入位置 | 注入方式 | 生命周期 |
|------|------|---------|---------|---------|
| **A. 角色系统提示词** | 各 `run*` 函数硬编码 `promptLines` | system 头部 | 字符串拼接 | 每次请求按 AgentKind 重建 |
| **B. 工具使用规约** | `toolCallingSystemSuffix()` | system（A 之后） | 字符串拼接（`\n`） | 静态常量 |
| **C. 记忆注入块** | `RenderPromptContext()`（①②④ 层记忆） | system（`## Agent Memory` 段） | 字符串拼接（`\n\n`） | 每次请求实时渲染 |
| **D. 对话历史** | `SessionConversation.Turns`（③ 层记忆） | system 之后的 message 序列 | message 追加 + 压缩 | 持久化、每轮更新 |
| **E. 失败分析指令** | `failureAnalysisInstruction` 常量 | message 尾部 | 追加一条 human 消息 | 瞬时（仅失败路径） |

#### A. 角色系统提示词（按 AgentKind 分流）

不同角色注入不同的 system 头部，同时决定可用工具集与可委派对象：

| AgentKind | 提示词要点 | 可委派工具 | 位置 |
|-----------|-----------|-----------|------|
| `Router` | "你是 RouterAgent，负责协调本地 Agent……优先 coder_agent 再 reviewer_agent" | `coder_agent`、`reviewer_agent` | runtime.go:244 |
| `Default` | "你是通用代码代理运行时……优先调用可用函数" | 全部本地工具 | runtime.go:267 |
| `Coder` | "你是 CoderAgent，负责真实完成实现/编码……" | `router_agent`、`reviewer_agent` | runtime.go:305 |
| `Reviewer` | "你是 ReviewerAgent，负责代码审查/风险识别……" | 无工具（纯 LLM，走 `runPlainLLMTask`） | runtime.go:328 |

#### B. 工具使用规约（`toolCallingSystemSuffix`）

对所有带工具的角色统一追加的行为约束（runtime.go:427），包含：
- **编辑约定**：改文件先 `read_file` 再 `edit_file` 原子操作；`write_file` 仅新建；删整个文件用 `delete_file`。
- **路径与参数**：相对路径、正斜杠、避免 JSON 转义错误。
- **执行流程**：先输出「## 执行计划」→ 逐步执行并回报进度 → 最终结论。
- **错误与收尾**：工具报错先读 error 修正重试；无法完成必须输出中文失败分析。

#### C. 记忆注入块（`RenderPromptContext` → `## Agent Memory`）

这是**分层记忆进入提示词的唯一通道**，把 ①②④ 层聚合成一段 Markdown（`internal/data/memory/usecase.go:195`）：

```
RenderPromptContext(sessionID):
  user    = LoadUser(userID)            # ① 用户记忆
  session = LoadSession(sessionID)      # ② 会话记忆
  block   = formatAgentMemoryForPrompt(user, session)   # 渲染工具提示/技能/命令策略/prompt_notes
  records = ListSessionErrors(sessionID, limit=6)        # ④ 最近 6 条错误
  block  += formatSessionErrorsForPrompt(records)        # 追加错误块
  return block
```

- `formatAgentMemoryForPrompt` 把用户段与会话段拼成 `### 用户记忆 / ### 会话记忆`，逐条渲染 `ToolHints / SkillHints / CommandPolicies / PromptNotes`（`internal/data/memory/helpers.go`）。
- 错误块让模型看到自己近期的失败，形成**自我纠错闭环**。
- 空记忆时返回空串，不注入 `## Agent Memory` 段（零污染）。

> 注意：③ 对话记忆**不走这里**，它作为独立的 message 序列注入（见 D），因为它是对话结构而非 system 文本。

#### D. 对话历史（③ 对话记忆 → message 序列）

对话历史不是 system 文本，而是 `system` 之后的 `human/ai/tool` 消息序列，注入前会先**压缩**：

```
turns = LoadConversation(sessionID).Turns          # ③ 层
turns = AppendHumanTurnIfNeeded(turns, prompt)     # 补当前用户输入
turns, meta = PrepareTurnsForLLMWithMeta(turns)    # 超阈值则压缩旧 tool 输出、省略中间轮、保留最近 N 轮
messages = BuildLLMMessages(systemText, turns)     # [system, ...turns]
```

- 压缩触发阈值 `DefaultCompressThreshold ≈ 200,000 字符`，保留 `DefaultKeepRecentTurns = 24` 轮（见运行时设计文档「关键参数」）。
- **工具循环每一轮都会重新压缩并重建 messages**（runtime.go:478-484），保证长循环不撑爆上下文。
- `system` 文本（A+B+C）在整个循环中保持不变，只有对话历史部分随轮次增长与压缩。

#### E. 失败分析指令（瞬时注入）

仅当工具连续失败达 5 轮、总循环达 12 轮或 LLM 返回空时，`finishWithFailureAnalysis`（runtime.go:615）在**已有消息尾部追加一条 human 消息**：

```go
instruction := failureAnalysisInstruction        // "【系统通知】……请不要再调用任何工具，直接输出中文失败分析：目标/已尝试/根因/建议"
if cause != nil { instruction += "\n\n最后一次错误：" + cause.Error() }
analysisMessages := append(messages, TextParts(Human, instruction))
response := modelClient.GenerateContent(ctx, analysisMessages)   // 不带 tools，强制文本收尾
```

- 该指令**不进入任何持久层**，是一次性的收尾引导。
- 生成的失败分析会被 `persistConversation` 写回 ③ 对话记忆，并经 `RecordSessionError` 落入 ④ 错误记忆。

### 2.3 注入方式对照：system 拼接 vs. message 追加

| 维度 | system 文本拼接（A/B/C） | message 追加（D/E） |
|------|------------------------|---------------------|
| 形态 | 单条 `system` 消息的多段字符串 | 独立的 `human/ai/tool` 消息 |
| 可变性 | 循环中固定不变 | 每轮增长/压缩（D）或尾部追加（E） |
| 承载记忆 | ①用户 ②会话 ④错误 | ③对话 |
| 组装函数 | `runToolCallingLoop` 内联拼接 | `BuildLLMMessages` / `finishWithFailureAnalysis` |

## 三、记忆与提示词的完整数据流

```
                        ┌───────────────── 每次调用 LLM 前 ─────────────────┐
[用户输入 prompt]        │                                                   │
      │                 │  ① LoadUser ──┐                                    │
      ▼                 │  ② LoadSession┤─► RenderPromptContext ─► C 记忆块  │
StartConversation ─► ③  │  ④ ListErrors─┘         │                          │
      │                 │                          ▼                         │
      │                 │  A 角色词 + B 工具规约 + C 记忆块 = systemText      │
      │                 │                          │                         │
      ▼                 │  ③ LoadConversation ─► 压缩 ─► turns               │
runToolCallingLoop ─────┤                          │                         │
      │                 │  BuildLLMMessages(systemText, turns) = messages(D) │
      │                 └───────────────────────────┬───────────────────────┘
      ▼                                             ▼
  工具调用循环 ◄─────────────── ChatClient.Chat(messages, tools)
      │  成功 → RecordSessionToolUsage(②)  持久化对话(③)
      │  失败 → RecordSessionError(④)      追加 E 失败分析指令
      ▼
  TaskResult
```

**闭环要点**：本轮产生的工具使用写回 ②、错误写回 ④、对话写回 ③；下一次请求时它们又通过 C/D 被重新注入——记忆在「读注入 → 执行 → 写回」间循环增强。
